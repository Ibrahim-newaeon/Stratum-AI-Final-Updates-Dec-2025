The differentiator — the "Trust-Gated Autopilot" — is the weakest part of the product

The platform's entire pitch is automation that executes only when signal health passes a trust gate. The audit found that this exact spine exists as two divergent implementations, and the good one is not connected to anything users touch.

A genuinely well-built, weighted stratum/core engine (real Signal Health calculation + a real PASS/HOLD/BLOCK Trust Gate with configurable thresholds, 38 passing unit tests) is never exposed by any HTTP endpoint. The engine that is wired to the product reads a fact table fed by a placeholder rollup that isn't even registered in Celery Beat — so it returns no_data, and the frontend's trust routes 404 and silently fall back to demo mock data.

Likewise, Autopilot's enforcer, trust-gate check, and platform executors are all real and tested — but the execution pipeline is orphaned: the apply-actions Celery task is never registered or dispatched on approval, so approved autopilot actions never actually run. The block/soft-block enforcer sits behind an endpoint nothing calls, and a router double-prefix 404s the frontend. Net: the core value proposition is demonstrable in pieces but not yet real end-to-end. This is the single most important thing to fix before any launch that markets "trust-gated autopilot."

06 Recommendation

Don't shelve it, and don't wait to "fix everything." Ship a phased private beta around the spine — but fix the trust-gated-autopilot core first, because that is the one thing you can't launch without.

The audit's dominant pattern is encouraging: the expensive work is done. Real algorithms, real platform integrations, encrypted token storage, tenant isolation, and substantive test suites exist almost everywhere. What's broken is the cheap "last mile" — and it repeats in just three shapes, which means it's fixable in weeks, not months.

Phase 01–2 weeks · unblock
  • Wire the real Trust Engine to an endpoint, schedule the rollup task, fix the frontend trust routes. This is the product's whole thesis — it cannot ship on mock data.
  • Connect Autopilot to the signal-health gate (not just budget/ROAS thresholds) and add the autonomous evaluation loop to Celery Beat.
  • Fix Auth invite-accept (no backend route today) — blocks all team onboarding.
  • Fix the FE↔BE contract drifts (Pacing, Profit, Attribution, Multi-tenancy URL prefix) — mechanical, high-leverage.
Phase 1launch · flag off the rest
  • Go live with the spine: Auth + MFA + Payments + CDP + Audience Sync + Reporting + Trust Engine + Autopilot.
  • Feature-flag off everything below ~65%: Drip, WhatsApp, Competitor Intel, Campaign publish, Profit/Pacing UI. Nobody buys a trust-gated-autopilot product for the drip builder.
  • Register the unregistered Celery tasks (Newsletter, alerts) or hide the features that depend on them — never ship a button that silently does nothing.
Phase 2fast-follow
  • Backfill Partial features: Rules worker schema fix, Campaign real publish, EMQ serving-layer unification, WhatsApp async pipeline, CAPI persistence + DLQ wiring.
  • Replace fabricated serving data (SuperAdmin infra metrics, Competitor random data) with real sources or honest empty states.

What's genuinely real (protect it)

  • Algorithms & math — signal health, EMQ, Markov/Shapley, EWMA pacing, z-score, profit calc are all real and tested
  • Platform integrations — OAuth for all 4 ad platforms, HubSpot, Stripe, Slack, real API executors
  • Security — MFA, JWT rotation, Fernet token encryption, RBAC, tenant isolation
  • CDP — the most complete surface, launchable today

The 3 recurring failure shapes

  • Contract drift — frontend calls routes/shapes the backend never exposed (Pacing, Profit, Attribution, Trust)
  • Unwired execution — Celery tasks commented out, unregistered, or schema-diverged (Drip, Newsletter, WhatsApp, Rules, Campaign publish)
  • Mock leaking into serving — real logic bypassed by fabricated/demo data (EMQ, Anomalies, FocusPane, Competitors, SuperAdmin)
